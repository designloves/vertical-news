Vendor study: AI coding agents reuse approved design-system components in only 55–59% of tasks

It puts numbers on design-system drift when coding agents work in large, old codebases.

DesignVerse, which sells a context layer for coding agents, tested standard agent setups on 15 enterprise codebases, each 15 to 20 years old and over a million lines, in sectors including aviation, banking and defence. Out of the box, agents used the organisation's approved internal components in 55–59% of tasks. With DesignVerse's own system the figure was 92%.

Consistency was also low. Given the same task several times, standard agents produced the same answer 61–69% of the time, against 97% with the context layer. Without it, agents read a median of 10 tokens for every accepted token of code, and up to 150 on one legacy system.

This is a vendor testing its own product on its own clients and prospects, so the comparison should be treated with care. The basic finding still matters for frontend and design-system teams: agents tend to rebuild components rather than reuse them unless they are given the right context.
