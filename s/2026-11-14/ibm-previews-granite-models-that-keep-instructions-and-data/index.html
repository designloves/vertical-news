IBM previews Granite models that keep instructions and data apart to resist prompt injection

Teams building agents and AI features into products need ways to stop documents, web pages and tool results from hijacking the model.

IBM's Granite team has released experimental 3B and 8B versions of Granite 4.1 that use LLMON, a new markup format for model input. Instead of ordinary characters such as JSON brackets, LLMON uses reserved special tokens to mark each part of the context as an instruction, data or a requirement, and an explicit block says which instruction to run on which data. Text inside documents or tool results is meant to be read as material, not followed as a command.

IBM reports that on the OPI benchmark the models nearly eliminate successful indirect prompt injections, avoiding 47% more attacks than the best frontier model it tested, with similar trends on two other benchmarks. General performance is said to match the standard Granite 4.1 Instruct models. The tests cover static attacks only; defence against adaptive, multi-turn attacks is still in progress, and IBM notes the behaviour is learned, not guaranteed.

The models, a toolkit and converters to and from JSON are on Hugging Face and GitHub. IBM calls this a preview for evaluation, not production. Results are vendor-reported.
