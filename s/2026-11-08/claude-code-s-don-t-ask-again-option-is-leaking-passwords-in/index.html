Claude Code's 'don't ask again' option is leaking passwords into public GitHub repos

If your team uses AI coding agents, a settings file you never look at may be publishing your credentials.

Security firm Apiiro reports that when a Claude Code user approves a shell command with 'Yes, and don't ask again', the tool saves an allow rule in .claude/settings.local.json. If the approved command contained a password or token, it is stored in plain text. The tool excludes the file from git globally on the user's machine, but not in the project's own .gitignore, so it often gets committed.

Apiiro found 1,122 of about 104,000 public copies of the file (roughly 1.1%) held at least one secret, 1,379 in all, including 379 database passwords and 23 AWS keys. Counting other agent files and chat logs, the total reaches 2,539 secrets in 1,994 repositories. Popular scanners missed many of them, because the passwords sit inside commands. The Hacker News says earlier reports to Anthropic were closed automatically and it reported no reply from the company.

For product and engineering teams the advice is practical: rotate any exposed credentials first, untrack the file, approve command patterns rather than exact commands, and treat agent folders like .env files in pre-commit and CI scanning.
