Startup uses an OpenAI model to find 'Java4Shell', a critical flaw in Java 17 to 27

The case shows AI speeding up bug-hunting on both sides, and many backends, build tools and test rigs run on Java.

Security startup Calif disclosed CVE-2026-114938, nicknamed Java4Shell, on 17 November. It is a memory-corruption bug in the fast Base64 decoder of OpenJDK's HotSpot runtime that can lead to remote code execution. Calif rates it 9.2 out of 10, and Oracle rates it 8.1. The New York Times reported that Calif found it with OpenAI's GPT-6 Cyber, while Calif's own account credits Codex and about an hour of work.

It affects Java 17, 21, 25 and 27 on x86-64 processors with AVX-512 VBMI. ARM64 and standard Java 8 and 11 are not affected. Oracle, Eclipse Temurin and Amazon Corretto have released fixed builds (for example 17.0.21.1 and 21.0.13.1), and Red Hat is preparing fixes. As a stopgap, the decoder can be disabled with a JVM flag. As of 18 November there were no confirmed attacks.

Engineering teams should check servers, CI runners and simulation or test tooling that run Java, not only customer-facing apps. With models now finding serious bugs in about an hour, it makes sense to shorten patch cycles.
